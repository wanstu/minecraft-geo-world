# GeoWorld v0.1.4

## 中文

### 改进

- 创建 GeoWorld 世界时不再要求先手动“生成模型”才能继续；点击继续后会按当前设置自动完成模型生成并进入原版创建流程。
- 新建世界的“矿区地表原矿堆”默认开启。旧存档以及缺失该字段的旧配置仍保持关闭语义，不会因为升级而改变已有世界行为。
- 优化 WebUI 矿物筛选：切换“全部矿物 / 锌 / 铁 / 钻石”等条件时不再清空并重建整张 SVG 叠加层，只更新矿物节点与矿物 Canvas。
- 完成跨维度 WebUI 行为：离开主世界后暂停主世界位置联动、隐藏玩家标记并禁用不安全的坐标操作；回到主世界后自动恢复，无需刷新页面。
- 补齐 1.21.1 NeoForge / Fabric 的矿区原生方块放置回归，覆盖模组矿物映射、主矿/伴生矿、地表矿堆和水下矿堆。

### 实机验收

- Minecraft 1.21.1 NeoForge + Create、Seed `123456`：模组矿物、主/伴生矿关系、地表矿堆、水下矿堆均通过。
- 快速切换矿物筛选时图标正确且无整图重绘卡顿。
- 实际进入下界后 WebUI 正确暂停主世界联动，返回主世界后自动恢复。
- 自动验证包括 Go 测试、WebUI 回归、矿区原生放置检查以及 1.21.1 NeoForge 完整 `check jar`。

### 兼容性

世界模型格式、Query API v1 和生成规则版本保持不变。已有世界继续使用锁定模型，不会重算已生成区块。请选择与 Minecraft 版本和 Loader 完全匹配的 JAR。

## English

### Improvements

- Creating a GeoWorld world no longer requires a separate manual “generate model” step. Continuing from the GeoWorld settings now generates the model automatically before entering the vanilla creation flow.
- Surface ore piles are enabled by default for newly created worlds. Existing saves and legacy configs with no `surface_ore_pile` field keep the previous disabled behavior.
- Mineral filtering in the WebUI no longer destroys and rebuilds the full SVG overlay. Switching between all minerals, zinc, iron, diamond, and other filters only updates cached mineral nodes and the mineral canvas.
- Overworld-linked WebUI actions now pause outside the Overworld, hide the player marker, and disable unsafe coordinate actions. Returning to the Overworld resumes automatically without reloading the page.
- Native Minecraft mining-material regression coverage now verifies modded mineral mappings, primary/companion ore placement, surface piles, and underwater piles on Minecraft 1.21.1 NeoForge and Fabric.

### Live acceptance

Minecraft 1.21.1 NeoForge with Create and seed `123456` passed live checks for modded minerals, primary/companion assignments, surface piles, underwater piles, mineral icon/filter interaction, and Nether-to-Overworld WebUI pause/resume behavior.

The world model format, Query API v1, and generation-rules version are unchanged. Existing worlds keep their locked models and already-generated chunks are not regenerated.
