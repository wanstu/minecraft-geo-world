# GeoWorld R8.1：水文一致性专项设计与固定回归

日期：2026-11-11。状态：**R8.1a 只读诊断与样本冻结，未修改生成算法、未发布新 JAR**。

基线：v0.1.5-rc.4，规则 geoworld-rules-v1.1.22，精确种子 -1818694639628404530，320×200 节点 / 128 方块间距 / Standard。

## 1. 原则：先判断责任层，再修改

用户截图揭示海面高于入海河口、大河预览无明显出海口、天坑切开河谷但缺乏合理排水关系。这些现象不能仅凭现有 R1/R2 中心线检查证明或排除。

必须分四层：
1. Hydrology / Reconcile：河网 DAG、汇流、出海/入湖、内流与失流归因。
2. Waterbed / WorldSample：中心线、横断面、河床、水面、河口与两岸共同几何。
3. SpecialFeatures：天坑与正式河网的冲突；先评估选址，不硬造支流。
4. Minecraft Voxel + Web 地图：实际 Anvil 方块水体与地图预览是否和模型一致。

模型检测只标为 investigation_signal。不能因为拓扑有 OceanMouth 就断言河口方块连续；也不能因为截图没有可见出海口就立即修改 FlowTo。

## 5. 下一阶段 R8.1b 的验收门槛

**拓扑：** 按 From→To 完整追溯每条河流的终点，分海、湖、合理内流、合理失流、不明终端，不强行要求所有河流入海。分支汇流不能产生无归属的终点。

**河口：** 在正式入海河 t=0.75、0.90、0.98、1.0 及上下游 ±16/32/64 方块采样模型海水、河面、河床和干岸；实际 Minecraft 中抽取水方块、岸高和海床，使用四邻域检查连通。水墙、高架河道、悬空水、无法解释的断口为候选缺陷；不能单凭水面和海平面数值差就判失败。

**天坑：** 对 #11 天坑与 #735 河段同时抽取 SpecialFeatures 前后的地形和水体、实际水方块及周围干岸。如果破坏原河道，优先考虑不允许此天坑选址或尊重原河道；只有已有明确排水路径时才可建立落水洞/地下排水。禁止没有地质理由就强制添加地表支流。

**跨层核对：** Model、Minecraft BlockStates、Web 地图坐标必须一致；未生成的 Chunk 一律标记 not_generated，不能当成干地。任何模型-only 报告都不能替代方块级验收。

**回归：** 历史 v0.1.4、v0.1.5-rc.4 规则锁定，R7.2 控制源头不回退；如果确定需要改变生成语义，另起新 rulesVersion，执行 Go 回归、Java parity、1.21.1 NeoForge 真方块检查、最后九版本 CI。

## 6. 责任边界与停止条件

R8.1a 到此为止：设计文档、固定案例、模型只读检测工具及复现基线交付，不修改 worldgen。R8.1b 要先获得海口、断流图和天坑三个样本的真实方块证据，再定位到具体责任层做有限改动；不允许只因一个统计量异常就把所有水面整体平滑。
