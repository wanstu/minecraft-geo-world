# R7.2 真实宽河源渐变（版本隔离）

日期：2026-11-10。基线：v0.1.5-rc.3、规则 `geoworld-rules-v1.1.21`。本轮候选：`geoworld-rules-v1.1.22`、RiverGeometryVersion=7。

## 背景和证据

- dadm 游戏里使用 Seed `-1818694639628404530`、MC1.21.1 NeoForge、Standard 新建 v1.1.21 模型。
- 真实 Anvil 保存区块证明：河段 #48 `(-3264,-1856)->(-3264,-1728)` 是**没有上游输入**的源段（From 27334、To 27654），下游有 #179 接续。
- 它的半宽约 16.86 方块，在上游约 24 方块内由无水扩展至约 33 方块宽。视觉呈突然放大的圆头；不是断河、岸线重复、或截图渲染错误。
- 旧版已把河段侧向弯曲偏移从 0 改为 -10.88 方块；所以不再通过加大曲率解决这个宽度问题。

## R7.2 实现边界

- **只处理** RiverGeometryVersion >= 7 且河流 DAG 中无上游入段、长度 >=96、半宽 >=10、且不处于河口/湖泊进口/湖泊出口的常规河段。
- `waterbed.RiverSegment.HeadwaterTaper` 持久化到模型。现有存档缺省 false（不会从当前版本号猜测其存在）。
- 源头半宽 `max(3.5, 0.25*HalfWidth)`，沿首段前 65% 以 `smoothstep` 渐变至原半宽，之后保持原宽。
- 水域判定、河床横断面的 wet core、干岸坡过渡和河岸保护都使用 `riverMouthHalfWidth` / `riverBankBlendForSegment` 共享的局部宽度，避免只缩小水面不调整床岸。
- 原持久化纵剖面及水面高程保持不变，**源头水深随局部宽度减小、河床同步上抬**；弯曲后河床仍顺坡，不引入孤立源水或人工水面台阶。
- 不改变河网节点和连接关系，不改变矿业、建筑、下界/末地或地图工具；旧 v1.1.21 及更早模型保持原有几何和读取路径。
- Java 客户端当前版本识别改为 v1.1.22，同时保留所有历史 gate；生成缓存版本升级以防止误读旧生成结果。

## 验收门槛

1. `TestV122HeadwaterTaper`：源头最小宽度、单调渐变、下游恢复原宽、旧段维持固定宽度。
2. `TestV122NaturalHeadwatersPreserveLegacyWorldGraph`：同 Seed v21/v22 对照，固定河网、纵向 Profile 和宏观沉积，只给符合条件的源头添加标志；测试种子 123456 / MainRiverScale=2 的 34 条河段中 5 条可触发。
3. 现有 `TestV115OrdinaryRiverInnerWetCoreHasNoDryHoles` 按权威 `waterbed.RiverHalfWidthAt` 计算局部湿润核心；不可错误拿下游总宽度检查被刻意缩窄的源头。
4. `go test -p 2 -count=1 ./...` 整仓检查，原 v21 数据模型 Golden 校验，1.21.1 NeoForge 的 `gradlew check --offline`，最终九个适配版本 CI。
5. 独立创建 **v22 世界**，以真实生成 Minecraft 保存区块核对同一河源：水宽按距离逐步增加、没有异常截断/多方块水面突跳/岸地低于水面、无未解释的区块接缝。仅靠模型蒙层不得宣称实际方块验收通过。

## 真实模型对照结果（已完成，不等同实际 Minecraft 区块）

- 同一个 Seed `-1818694639628404530`，dadm 保存的历史模型 v21 与用当前 v22 Go 引擎**独立生成**的 320×200 节点完整模型，对照 953 条河段全部一致，只有 5 个源头新增布尔标记。
- 源段 #48：(-3264,-1856) → (-3264,-1728)，半宽由起点 4.214、t=0.325 时 10.536，至下游恢复为 16.858 方块；弯曲偏移仍为 -10.88。
- 原源头河床归一化高度 0.53550，新版 0.54269；完整水面高程两版均为 0.54675，说明 source depth taper 没有造成人工水面阶梯。

### Java 运行时一致性补丁（2026-11-10）

- 静态检查发现 Java `GeoWorldV1.RiverSegment` 早先没有解析新增的 `HeadwaterTaper` 属性。虽然 Go 模型正确，新版 Minecraft 会错误复用未收窄宽度。现已修复 Java 读取、湿润核心、河床水深、岸坡/岸线保护路径，局部宽度与 Go 原生引擎共用相同数值函数。
- 使用完整 v1.1.22 已保存世界模型，对河源及下游 **231 个坐标**执行 Go 与 Java 独立运行时采样对照（水体类型、地面高程、水面高程、水深），**全部数值相等**；其中 66 点为河流水体。
- 使用历史 dadm v1.1.21 世界模型执行相同 231 坐标交叉回归，也 **完全相等**，排除 Java 补丁破坏旧存档的直接证据。
- 完整跨语言/实际区块正式验收仍以 GitHub CI 与新建 v22 Minecraft 世界为准；命令和本地探针位于被 Git 忽略的 `.tmp/r7-visual/R72JavaParity.java`、`r72_go_parity.go`。

**停止/发布门槛：** Go 全量回归与 GitHub 九版本 CI 必须通过；必须用新建 v22 Minecraft 世界读取 Anvil 方块列并形成真实截面证据后才可发布 rc.4。旧 `ttt` / dadm 历史 `New World` 不能修改。
