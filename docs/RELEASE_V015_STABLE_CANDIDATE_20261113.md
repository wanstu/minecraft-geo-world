## CI 安全性变更

本分支仅在 `.github/workflows/release.yml` 增加明确的事件门禁：

- `workflow_dispatch`、`pull_request`、普通分支：运行 Windows 九目标实现检查，但**绝不运行 release-build / publish**。
- 只有 `push` 发行 `v*` tag 可以进入 release-build / publish，且发布构建已有的检查要求 tag **等于当前 master 的 commit**。
- 发布时 Gradle 使用工作流传入的 `-Pmod_version=<从正式标签推导>`；仓库中的开发期 `gradle.properties` 仍可保持 `mod_version=0.1.4`，不能将开发 JAR 当成正式 0.1.5 JAR。
- 新增 `scripts/test_v015_stable_release_gate.py`：检查稳定规则绑定、九个适配器矩阵一致、手动触发永不发布和标签版本传入条件。

## 玩家可预期的范围

GeoWorld v0.1.5 的可发布范围以 RC4 的已完成水文与侵蚀沉积改良为基础，而不是承诺天坑、世界海岸、河口、山区以及全部现实地貌都已经完全自然。原有单世界模型、WebUI、矿区/矿堆及创建世界流程延续 v0.1.4 的已验收行为。若需要追求真实地貌整体达标，继续以隔离版本推进，不阻塞已成熟功能的稳定发布。
