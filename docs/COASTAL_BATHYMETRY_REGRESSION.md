# GeoWorld 海岸水下坡度修复：实机坐标回归（2026-10-11）

## 现象

用户在 Seed `-563659577384754347`、新世界 `t29` 的图片：
- `X≈-6289, Z≈3374`：沙岸靠海的一面像立起来的台阶，继续调低**干地**高度无改善。
- `X≈-6586, Z≈4090`：海岸一侧的狭窄内凹水域看似和大海之间有沙带；此坐标本身位于大片海水中，不能仅凭相机视角确认整个水域已经断开。

实际 HMCL 26.3 `latest.log` 21:13..21:16：
- 激活 Seed `-563659577384754347`、`t29`、动态 GeoWorld 模型；
- 累计4224区块，平均 model=0、shoreline=6.085ms、biomes=14.797ms、voxel=6.702ms、minerals=0.139ms、geodes=0.007ms；
- 两次 `Can't keep up` 6735ms / 134ticks、2547ms / 50ticks；
- 这些是旧版（本轮修复之前）真实客户端数据。

## 直接原因：水边的海床，而不是原始干岸太高

在 81×81 区域 `(-6289,3374)` 使用真实 `GeoWorldShoreline.ChunkPlan` 重新计算，近岸是 `Rolling Plain`，陆地模型地面约Y60，海面Y63。为防海水从干地逃逸，原 `oceanBackshoreMinimum` 会将最近一两列干岸抬高约3格；但潮下 `Ocean` 的第一列床面仍是Y59左右（4格水深），导致**水下床面直接碰到抬高的沙堤，视觉是连续垂直沙墙**。

之前新增的 `gentleBankCap` 只会将过高的干地**压低**，对这里的低洼原地形完全不触发：`candidates=0 altered=0`。不能再扩大 dry-bank taper 半径解决此问题。

## 修正：条件性浅水床坡

- 在 `GeoWorldShoreline.planColumn` 的既有 `Ocean/Lake` 已拥有的水体列，检查 1..4 方块曼哈顿范围内是否存在非岩石型干地（不包括 Canyon 或自然岩壁）。
- 当水深本身为2..8格时，按离干岸的距离 d 将海床最低边界设为 `waterBoundary-d`：例如最邻近陆岸d1保持1格水深，再向外逐渐过渡成2/3/4格水深；不再制造水下3..4格垂直断面。
- 只**抬升近岸水下的河床以外的湖海底**，不移动湖海水面，不增加或删除水源，不将水改派给其他水体，不改变模型的宏观水系。更深的海床、岩壁/峡谷地形、河流/湿地不受该额外规则影响。
- 不更改 GeoWorld 外普通 Minecraft 世界，不注册新方块、生物或实体。MOD 删除后，原版机制保持不变。
- 使用原区块 `Neighborhood` 缓存样本读取，不进行额外调用昂贵的 `runtime.sample()`。降低查询的范围为湿地之外、中浅水且邻近普通干岸，避免对深海整体改造。

## 坐标专项验证与水体保护

新增 `probeGeoWorldReportedCoast` 自动在 Seed `-563659577384754347` 生成两处实际 `ChunkPlan` 及交界坡度，加入 Gradle `check`。

- `(-6289,3374)` 周围81×81内，紧贴陆岸、水深≥4格的湿格由72→0；水下修整列数210；最终湿/干交界最大落差1格，wetDryCliffs(>2格)=0。没有更改水体类型与水面。
- `(-6586,4090)` 同大小区域 6553格为模型 Ocean 水体，已拥有连续大片海水；照片中偏离玩家坐标的狭长凹入水域是否封闭仍须更精确的位置/视觉复核，本轮不擅自填埋。
- `verifyGeoWorldWaterOwnership` Seed123456 全部302848列所有异常（unowned/unsafe/freeFall/lost/riverPeak/wetlandLeaks等）=0；`verifyGeoWorldShoreline` 通过，旧窄沟/小坑/岸线前缘及 point-plan mismatches 均0。
- `benchmarkGeoWorldChunkPlanning` 单独进程测试48区块：shoreline=3.910ms，之前独立模型基准4.123ms；运行噪声不可据此认定增速，至少目前没有明显回退。**真实 HMCL 性能须待下次用户加载新区块后检查 t30+ 的日志。**
