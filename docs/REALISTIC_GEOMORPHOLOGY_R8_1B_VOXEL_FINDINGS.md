## 4. 问题源头定位到 Waterbed 与 Ocean 交接

代码层的重点组合：

1. Waterbed 的正式 OceanMouth receiver 标记正确，海洋接收面为 normalized 0.5（Minecraft 海面 Y=63）。
2. Waterbed.Sample 会调用 riverBankSurfaceCeiling，取附近低干岸高度作为上限；即使 RiverSegment 的 ReceiverSurface=0.5 已持久化，部分河段的实际自然 river surface 仍被按低岸压到 0.5 以下。
3. WorldSample.Sample 在 OceanEligibility 满足条件后，直接把水面切换到固定海平面 0.5。
4. 因此同一条河会在河流区保持过低水位，进入海洋归属时跳回海平面，形成 +1 甚至 +4 格的逆升。

**禁止的伪修复：** 仅把河面强行抬高到海平面但不处理两侧干岸，会重新制造高架河或河水外溢。也不能统一抹平所有海岸坡面。

正确的下一阶段 R8.1c 应把河口水面、河槽和实际岸坡的约束一起处理，明确哪些海岸低地应自然被海水淹没，哪些河谷应调整地形；同时与 Java Runtime 同义实现并使用新的规则版本隔离。

## 5. 天坑与河道的第二项模型级缺陷

- 天坑 #11，中心 (-1600,5312)，实际与河道 #735 的地貌影响范围相交，未有对应排水规划。
- 同一河段约 (-1699,5347)：河面预测 Y=98，而一侧距河心 16 格的干岸地面 Y=80、32 格的地面 Y=71。
- 河道没有降低水面，周围天坑陆地却被大幅下切；形成约 18～27 格的高架河-坑底高差。
- **尚无该坐标实际 Anvil 方块验收**，目前属于可复现的模型几何缺陷。
- 修复优先级：先排除不具备合理排水关系的天坑候选选址，再评估自然河流绕行或地下排水；不可自动凭空创造支流。
